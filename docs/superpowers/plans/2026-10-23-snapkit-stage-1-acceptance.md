# Snapkit, этап 1 — приёмка

Что проверить вместе с пользователем перед слиянием ветки `feat/stage-1-mvp` в `main`.
Программа уже установлена: `%LOCALAPPDATA%\Programs\Snapkit`, ярлык «Snapkit» в «Пуске».
Если что-то пошло не так — журнал `%LOCALAPPDATA%\Snapkit\log.txt`.

## Перед началом (делает Claude)

- [ ] Разблокировать компьютер и прогнать все тесты, включая буфер обмена:
  `dotnet test Snapkit.slnx`. В пятницу тесты буфера не запускались: компьютер был
  заблокирован, и Windows никому не давала открыть буфер.

## Главный сценарий (раздел 14 описания)

- [ ] **1. Снимок.** Print Screen → выделить область → рамка → комментарий → Enter.
  Кружок A1 есть → «Готово». В ленте карточка A, значок комментария 1.
- [ ] **2. Второй снимок.** Стрелка и две заметки → в ленте A и B.
- [ ] **3. Claude Desktop + AutoHotkey.** Клик в поле ввода → **Shift+колесо вверх**:
  - в поле две картинки с кружками и текст «Снимок A / A1 — … / Снимок B / B1 — …»;
  - сообщение не отправлено;
  - после этого в Блокноте или в поле Claude набрать «абв» — буквы маленькие (Shift
    не залип), Ctrl не залип;
  - в журнале строка «Вставка пачки: … CompletedVerified». Если там CompletedUnverified —
    смотреть строку «Буфер во время вставки прочитал не получатель: …».
- [ ] **4. Chrome.** То же в claude.ai или ChatGPT — обычным Ctrl+V с клавиатуры.
- [ ] **5. Обычная вставка не ломается.** Сделать снимок, скопировать строку в PhpStorm →
  Ctrl+V вставляет строку, на ленте «Пакет вытеснен». «…» → «Копировать пакет» → Ctrl+V
  в чате вставляет пачку.
- [ ] **6. Смена окна.** Пачка из 5 снимков; во время вставки переключиться в другое окно →
  вставка остановилась, в другое окно ничего не попало.
- [ ] **7. Повторное открытие.** Клик по карточке → снимок на том же месте экрана,
  кружки на месте, разметку можно изменить.
- [ ] **8. Разный масштаб мониторов** (если удобно): поставить второму монитору 125 % или
  150 %, снять область на нём → снимок совпадает с экраном. Масштаб потом вернуть.
- [ ] **9. Восстановление.** 2 снимка → завершить Snapkit в Диспетчере задач → запустить →
  снимки на месте.

## Проверки по итогам независимого ревью

- [ ] **Win+L.** Заблокировать компьютер → войти → Print Screen открывает Snapkit,
  а не «Ножницы»; Ctrl+V с неотправленными снимками вставляет пачку.
- [ ] **Ctrl+Alt+Del.** Ctrl+Alt+Del → Esc → набрать «м» в любом поле — буква печатается,
  вставка пачки не запускается.
- [ ] **Alt+F4 в окне снимка.** Print Screen → Alt+F4 → снимок отменён. Следующий Print Screen
  работает, лента на месте.
- [ ] **Лишние щелчки колеса.** Вставить пачку и сразу ещё пару раз крутнуть Shift+колесо —
  текст комментариев не вставился второй раз.
- [ ] **Большая картинка.** Скопировать картинку больше экрана → «…» → «Вставить изображение
  из буфера» → открыть карточку → снимок не сжат и не искажён (край обрезан), рамки встают
  туда, куда рисуешь.

## Отложено на потом (мелкие находки ревью)

- Повторно проверять окно прямо перед программным Ctrl+V.
- Вернуть пакет в буфер после остановленной вставки.
- Если буфер занят посреди пачки, сообщение говорит «0 картинок», хотя часть уже вставлена.
- Готовить картинки для вставки заранее, а не во время вставки.
- Убирать оставшиеся `*.tmp` в папке сессии.
- Проверять выделение памяти под буфер (`GlobalAlloc`).
- Память на 20 больших снимков.
- Esc в поле «Комментарий к снимку».
- «Снимки восстановлены после сбоя» после каждой пересборки.
- Тесты пишут в настоящий журнал программы.
