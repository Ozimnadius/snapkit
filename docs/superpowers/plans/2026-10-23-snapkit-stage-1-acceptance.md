# Snapkit, этап 1 — приёмка

Что проверить вместе с пользователем перед слиянием ветки `feat/stage-1-mvp` в `main`.
Программа уже установлена: `%LOCALAPPDATA%\Programs\Snapkit`, ярлык «Snapkit» в «Пуске».
Если что-то пошло не так — журнал `%LOCALAPPDATA%\Snapkit\log.txt`.

## Перед началом (делает Claude)

- [x] Разблокировать компьютер и прогнать все тесты, включая буфер обмена:
  `dotnet test Snapkit.slnx`. В пятницу тесты буфера не запускались: компьютер был
  заблокирован, и Windows никому не давала открыть буфер.

## Ход приёмки

- 2026-10-26: на клавиатуре пользователя нет Print Screen — снимок по Ctrl+F12
  (`"captureHotkeys": "PrintScreen, Ctrl+F12"` в `settings.json`). Везде ниже Print Screen = Ctrl+F12.
- Найдено и исправлено по ходу приёмки:
  - одиночный снимок копировался без текста комментариев;
  - Alt+F4 в окне снимка бросал исключение (`Close()` внутри `Closing`), при двух мониторах
    второе окно могло остаться на экране;
  - в Chrome вставка заканчивалась «Проверить вставку не удалось»: Chrome читает текст, пока
    SendInput ещё не вернулся, и это чтение не засчитывалось.
- Проверка «Восстановление» дважды дала пустую ленту — это не ошибка программы. Claude Desktop —
  приложение MSIX, и Windows подменяет `AppData` для всех процессов, запущенных из него: Snapkit,
  запущенный из `build.ps1` в терминале Claude, жил в `%LOCALAPPDATA%\Packages\Claude_…\LocalCache`,
  а запущенный из «Пуска» — в настоящей `AppData` со своими лентой, настройками и журналом.
  `build.ps1` теперь запускает Snapkit через Проводник. Настоящую `AppData` из терминала Claude
  читать процессом вне пакета: `Invoke-CimMethod Win32_Process -MethodName Create`.
  Всё, что проверено до этого, от папки данных не зависит.

## Главный сценарий (раздел 14 описания)

- [x] **1. Снимок.** Print Screen → выделить область → рамка → комментарий → Enter.
  Кружок A1 есть → «Готово». В ленте карточка A, значок комментария 1.
- [x] **2. Второй снимок.** Стрелка и две заметки → в ленте A и B.
- [x] **3. Claude Desktop + AutoHotkey.** Клик в поле ввода → **Shift+колесо вверх**:
  - в поле две картинки с кружками и текст «Снимок A / A1 — … / Снимок B / B1 — …»;
  - сообщение не отправлено;
  - после этого в Блокноте или в поле Claude набрать «абв» — буквы маленькие (Shift
    не залип), Ctrl не залип;
  - в журнале строка «Вставка пачки: … CompletedVerified». Если там CompletedUnverified —
    смотреть строки «Чтение буфера при вставке: …» (кто, что и когда читал) и
    «Получатель не забрал данные за … мс».
- [x] **4. Chrome.** То же в claude.ai или ChatGPT — обычным Ctrl+V с клавиатуры.
- [x] **5. Обычная вставка не ломается.** Сделать снимок, скопировать строку в PhpStorm →
  Ctrl+V вставляет строку, на ленте «Пакет вытеснен». «…» → «Копировать пакет» → Ctrl+V
  в чате вставляет пачку.
- [x] **6. Смена окна.** Пачка из 5 снимков; во время вставки переключиться в другое окно →
  вставка остановилась, в другое окно ничего не попало.
- [x] **7. Повторное открытие.** Клик по карточке → снимок на том же месте экрана,
  кружки на месте, разметку можно изменить.
- [ ] **8. Разный масштаб мониторов** (если удобно): поставить второму монитору 125 % или
  150 %, снять область на нём → снимок совпадает с экраном. Масштаб потом вернуть.
- [x] **9. Восстановление.** 2 снимка → завершить Snapkit в Диспетчере задач → запустить →
  снимки на месте. (Прошла с третьего раза: первые два мешала подмена AppData — см. «Ход приёмки».)

## Проверки по итогам независимого ревью

- [x] **Win+L.** Заблокировать компьютер → войти → Print Screen открывает Snapkit,
  а не «Ножницы»; Ctrl+V с неотправленными снимками вставляет пачку.
- [x] **Ctrl+Alt+Del.** Ctrl+Alt+Del → Esc → набрать «м» в любом поле — буква печатается,
  вставка пачки не запускается.
- [x] **Alt+F4 в окне снимка.** Print Screen → Alt+F4 → снимок отменён. Следующий Print Screen
  работает, лента на месте. Проверить и до выделения области, и в редакторе; в журнале нет
  «ОШИБКА в интерфейсе». (Первая проверка прошла внешне, но журнал показал исключение — исправлено,
  нужна повторная.)
- [x] **Лишние щелчки колеса.** Вставить пачку и сразу ещё пару раз крутнуть Shift+колесо —
  текст комментариев не вставился второй раз.
- [x] **Большая картинка.** Скопировать картинку больше экрана → «…» → «Вставить изображение
  из буфера» → открыть карточку → снимок не сжат и не искажён (край обрезан), рамки встают
  туда, куда рисуешь. (Нашлись и исправлены две ошибки: картинка открывалась от угла экрана,
  а панель инструментов уходила под панель комментариев. Повтор проверил Claude через управление
  компьютером: рамка в файле ленты [1272,770 — 1727,1231] вокруг круга 1300–1700 × 800–1200.)
